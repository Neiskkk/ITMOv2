# Reflection — «Избранные питомцы»

## Решения
- UI: нативные кнопки, делегированный click, aria-pressed/aria-label, aria-live, фокус после re-render, пустое состояние и CTA.
- Логика: Set избранных id, строгая валидация JSON, исправляющая запись [], fallback в память, результат операций по контракту.

## Сложности
- Диаграммы Mermaid с кириллицей: потребовались правки для CLI-экспорта.
- Разделение ответственности UI/логика потребовало явного контракта по результату toggleFavorite и ошибкам хранилища.

## Исправления ИИ
- Исправлен формат результата UNKNOWN_ID (ok=false, changed=false, isFavorite=false, …).
- Обработка непустого, но не массива JSON как повреждённых данных.
- Сердце в кнопке (♡/♥) и адаптивность (минимум 44×44, скрытие текста на узких экранах).
- Одноразовое объявление недоступности хранилища после первого render.

## Доступность
- Полноценная клавиатура, видимый focus, aria-live="polite", без обязательных анимаций; иконка помечена aria-hidden.

## Плюсы/минусы
- GitHub Spec Kit: конвейер — constitution → specify → plan → tasks → implement; удобен для полного проектирования фичи и командной декомпозиции.
- OpenSpec: жизненный цикл — proposal/spec/design/tasks → apply → sync → archive; постоянные правила задаются через config.yaml; удобен для управления отдельным изменением и его архивированием.

## Личный вывод
- Комбинация подходов удобна: Spec Kit для быстрой декомпозиции, OpenSpec для долговременной устойчивости. Для учебного проекта дисциплина OpenSpec помогла избежать ошибок в контракте и доступности.
