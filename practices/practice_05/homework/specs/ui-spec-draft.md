## User Scenarios & Testing (mandatory)

### User Story 1 - Отметить питомца как избранного (Priority: P1)

Как посетитель каталога, я хочу отметить конкретного питомца как избранного прямо на его карточке, чтобы позже быстро вернуться к нему.

**Why this priority**: Это базовая ценность функции — сохранение интереса к питомцу одним действием.

**Independent Test**: Тестируется отдельно на одной карточке: наличие кнопки избранного, видимое переключение состояния, правильные aria-атрибуты, управление клавиатурой.

**Acceptance Scenarios**:

1. Given карточка питомца отображается в списке, When пользователь кликает по кнопке «Избранное», Then кнопка переходит в активное состояние (сердце заполнено), aria-pressed="true", отображается ненавязчивое подтверждение в aria-live.
2. Given кнопка в активном состоянии, When пользователь повторно кликает/нажимает Enter/Space, Then состояние возвращается в обычное, aria-pressed="false".

---

### User Story 2 - Показать только избранных (Priority: P1)

Как посетитель, я хочу быстро отфильтровать список, чтобы видеть только избранных питомцев.

**Why this priority**: Вторая половина основной ценности — быстрый доступ к избранному набору.

**Independent Test**: Переключатель «Только избранные» в шапке раздела «Питомцы» скрывает не избранные карточки; пустое состояние отображается корректно.

**Acceptance Scenarios**:

1. Given есть хотя бы один избранный питомец, When включён фильтр «Только избранные», Then отображаются только карточки с активной меткой избранного, счёт результатов соответствует ожиданию.
2. Given нет избранных питомцев, When включён фильтр «Только избранные», Then список карточек скрыт, показан блок пустого состояния с CTA «Вернуться к списку».

---

### User Story 3 - Совместная работа с поиском и фильтрами вида (Priority: P2)

Как посетитель, я хочу, чтобы поиск и фильтры «Все / Кошки / Собаки» продолжали работать, даже если включён режим «Только избранные», чтобы я мог быстро сузить избранных по критериям.

**Why this priority**: Сохранение единого ментального модели фильтрации; снижает когнитивную нагрузку.

**Independent Test**: При активном «Только избранные» поиск (только по имени питомца) фильтрует результаты в пределах избранных; переключатель вида (Кошки/Собаки) ограничивает подмножество.

**Acceptance Scenarios**:

1. Given включён «Только избранные», When выбран фильтр «Кошки», Then показываются только избранные кошки.
2. Given включён «Только избранные», When пользователь вводит в поиск «Мур», Then остаются только избранные карточки, чьё имя содержит «Мур» (без учёта регистра).

---

### User Story 4 - Клавиатурная доступность и фокус (Priority: P1)

Как пользователь клавиатуры, я хочу попасть на кнопку избранного на карточке Tab'ом, видеть заметный фокус и уметь переключать состояние Enter/Space.

**Why this priority**: Соответствие WCAG и конституции проекта.

**Independent Test**: Пройти карточки Tab'ом, убедиться в видимом фокусе на кнопке, активация Enter/Space переключает состояние и обновляет aria-pressed.

**Acceptance Scenarios**:

1. Given пользователь переходит фокусом на кнопку, When нажимает Enter, Then состояние переключается, фокус сохраняется на кнопке.
2. Given prefers-reduced-motion включён, When состояние меняется, Then нет навязчивых анимаций, только мгновенная смена иконки/заливки.

---

### Edge Cases

- Удаление последнего избранного при включённом «Только избранные»: сразу показывается пустое состояние без мерцаний.
- Длинные имена питомцев: aria-label не обрезается семантически, визуально текст кнопки может быть скрыт на мобильном (иконка + aria-label).
- Малые экраны 320 px: кнопка — иконка без текста, но с aria-label; не вызывает горизонтальный скролл.
- Переключение фильтра вида на пустое множество (например, избранны только собаки, выбран «Кошки»): показывается пустое состояние с подсказкой.

## Requirements (mandatory)

### Functional Requirements

- FR-001: На каждой карточке питомца отображается кнопка избранного (иконка сердца). Расположение: в верхнем правом углу карточки, доступна по клавиатуре.
- FR-002: Кнопка имеет два визуальных состояния: обычное (контурное сердце) и активное (заполненное сердце). Контраст соответствует WCAG AA; различие не только цветом (заливка/форма/толщина).
- FR-003: Кнопка является переключаемой (toggle). Атрибут aria-pressed отражает текущее состояние: false в обычном, true в активном.
- FR-004: Текстовые альтернативы: aria-label динамически формируется по шаблону: «Добавить в избранное: <Имя питомца>» для обычного и «Убрать из избранного: <Имя питомца>» для активного состояния.
- FR-005: При переключении состояния выводится ненавязчивое сообщение в живом регионе (aria-live="polite"): «Добавлено в избранное» / «Удалено из избранного» с именем питомца. Сообщение не перекрывает фокус.
- FR-006: В разделе «Питомцы» добавляется переключатель «Только избранные» (toggle/checkbox) рядом с существующими контролами фильтра. По умолчанию выключен.
- FR-007: При включении «Только избранные» список ограничивается карточками со статусом избранного. Существующий поиск (только по имени питомца) и фильтры «Все/Кошки/Собаки» применяются к этому подмножеству.
- FR-008: Пустое состояние при отсутствии избранных в текущем контексте отображает: иконку-состояние, заголовок «Нет избранных», подсказку «Отметьте сердечком понравившихся», кнопку/ссылку «Вернуться к списку» (выключает «Только избранные»).
- FR-009: Клавиатурная навигация: кнопка доступна в таб-цикле; активация клавишами Enter и Space; видимый фокус (например, контрастное кольцо) соответствует стилевому гайдлайну.
- FR-010: Состояния :hover, :focus-visible, :active оформлены; при :disabled (если применимо в будущем) — недоступно к взаимодействию и объявлено в aria-disabled.
- FR-011: Адаптивность: 
  - 320 px: кнопка — только иконка; размер и отступы не создают горизонтального скролла.
  - 768 px: иконка + короткий текст «В избранное» в обычном, «В избранном» в активном (опционально — допускается только иконка при ограничении места).
  - 1440 px: иконка + текст; выравнивание в единой сетке карточек.
- FR-012: Визуальная обратная связь при клике доступна сразу (меняется состояние кнопки мгновенно). Ошибки (если логика не подтвердила изменение) отображаются ненавязчивым уведомлением; состояние кнопки возвращается назад по сигналу логики.
- FR-013: Переключатель «Только избранные» сохраняет своё состояние в пределах текущего просмотра раздела до переключения пользователем (без требований к долговременной персистенции со стороны UI).
- FR-014: UI не раскрывает и не хранит персональные данные; подписи и aria-атрибуты не включают лишней информации помимо имени питомца.

### Key Entities

- PetCard (UI): визуальная карточка с атрибутами id, имя, вид (кошка/собака), статус избранного (boolean для отображения), кнопка избранного.
- FavoritesOnly (UI): булевый флаг состояния раздела «Питомцы»; влияет на набор отображаемых карточек и пустое состояние.
- SearchTerm (UI): строка поиска; применяется к текущему подмножеству (всех или избранных).
- SpeciesFilter (UI): значение переключателя «Все/Кошки/Собаки»; применяется к текущему подмножеству (всех или избранных).

### UI State Diagram (Mermaid)

```mermaid
stateDiagram-v2
    [*] --> ListingAll

    ListingAll: Список: все питомцы
    ListingFav: Список: только избранные

    ListingAll --> ListingFav: Toggle "Только избранные" ON
    ListingFav --> ListingAll: Toggle "Только избранные" OFF

    state ListingAll {
        [*] --> Unfav
        Unfav: Кнопка: aria-pressed=false
        Fav:   Кнопка: aria-pressed=true
        Unfav --> Fav: Click/Enter/Space
        Fav --> Unfav: Click/Enter/Space
        note right of ListingAll: Поиск только по имени и фильтры применяются ко всем карточкам
    }

    state ListingFav {
        [*] --> HasFavorites
        HasFavorites: Видны только избранные карточки

        state HasFavorites {
            [*] --> FavVisible
            FavVisible: Карточка в избранном (видна)
            FavVisible --> CheckRemaining: Unfavorite (Click/Enter/Space)
            CheckRemaining --> HasFavorites: Остались другие избранные (карточка удалена из списка)
            CheckRemaining --> EmptyFav: Удалено последнее избранное
        }

        EmptyFav: Пустое состояние
        EmptyFav --> ListingAll: CTA "Вернуться к списку" (выключает Toggle)

        note right of ListingFav:
            Список содержит ТОЛЬКО избранные; снятие избранного удаляет карточку из текущего списка.
            Поиск (только по имени) и фильтры вида применяются внутри этого подмножества.
    }
```

## Success Criteria (mandatory)

### Measurable Outcomes

- SC-001: Кнопка «Избранное» присутствует и доступна на 100% отображаемых карточек; смена состояния (вкл/выкл) выполняется одним действием (клик, Enter или Space) с мгновенной визуальной обратной связью.
- SC-002: Переключение состояния кнопки отображается визуально и объявляется ассистивным технологиям за ≤ 300 мс.
- SC-003: При включённом «Только избранные» 100% действий поиска и фильтров применяются только к избранному подмножеству.
- SC-004: Пустое состояние отображается для 100% случаев отсутствия результатов (нет избранных или несовпадение фильтров) без горизонтальной прокрутки на 320/768/1440 px.
- SC-005: Полная клавиатурная навигация: все элементы достижимы Tab'ом; Enter/Space переключают избранное; фокус визуально заметен.

## Assumptions

- Иконка сердечка используется как универсальный маркер избранного; текстовые подписи могут скрываться на мобильном.
- Переключатель «Только избранные» расположен в шапке раздела «Питомцы» рядом с поиском/фильтрами; по умолчанию выключен.
- Визуальные стили фокуса соответствуют STYLE_GUIDE проекта; дополнительных анимаций нет.
- Долговременная персистенция (если нужна) определяется командой логики; UI ожидает только текущее состояние для отображения.

## UI ↔ Логика: ожидаемый контракт и вопросы

### Ожидаемый контракт

- Входы UI:
  - Для каждой карточки UI получает признак isFavorite (boolean) и стабильный id питомца.
  - Текущее значение флага FavoritesOnly (boolean) при загрузке раздела (по умолчанию false, если логика не назначит иное).
- Сигналы от UI к логике:
  - toggleFavorite(animalId): пользователь переключил состояние избранного для карточки.
  - setFavoritesOnly(enabled): пользователь включил/выключил режим «Только избранные».
- Ожидания к обратной связи логики:
  - Подтверждение нового состояния избранного для id (success/failure) для синхронизации UI.
  - Актуальный признак isFavorite для карточек при любом изменении данных.

### Открытые вопросы для команды логики

1) Долговременность: следует ли сохранять состояние избранного между сессиями пользователя? Если да, UI должен ожидать начальное состояние от логики при входе.
2) Ограничения: есть ли лимит на количество избранных? Нужны ли предупреждения при достижении лимита?
3) Согласование ошибок: в случае отказа логики (например, несогласованность данных) какое сообщение/поведение предпочитается (текст уведомления, скрытая ретрай-логика произойдёт на стороне логики)?
