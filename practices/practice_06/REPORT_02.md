Цель: закрыть уязвимости, сохранённые в REPORT_01, сохранив полезную функциональность и границы стенда. Все проверки выполнены на реальном HTTP‑процессе исправленного сервиса.

- Исправленные уязвимости не воспроизводятся: подтверждено артефактами из `evidence/after/`.
- Файловая граница sandbox.py не нарушена; опасное удаление через API запрещено.

## Изменения в коде (service.py)

Ниже: проблема → исправление → место в коде → доказательство.

1) T1/T2 SQL Injection
- Проблема: конкатенация параметров в SQL (/profile, /search, /assistant/context).
- Исправление: параметризованные запросы (`rows_params`), привязка профиля к сессии; поиск доступен только staff.
- Код: `rows_params`; `/profile` (стр. 79–86), `/search` (86–93), `/assistant/context` (141–154).
- Доказательства: `evidence/after/T1_block_profile_sqli.json` (возвращён только собственный профиль), `evidence/after/T2_block_search_sqli.json` (403 staff only), `evidence/after/host.json`.

2) T3 Доступ к заказам без аутентификации
- Проблема: `/orders` возвращал все заказы анонимно.
- Исправление: требование токена; пользователю — только свои; staff — все.
- Код: `/orders` (93–100).
- Доказательство: `evidence/after/T3_block_orders_no_auth.json` (401 без токена).

3) T4 Произвольная цена
- Проблема: клиент мог задавать `price`.
- Исправление: цена всегда берётся из серверного каталога.
- Код: `/orders` (104–112).
- Доказательство: `evidence/after/T4_enforce_catalog_price.json` (цена каталога).

4) T5 Подмена роли X‑Role
- Проблема: роль бралась из заголовка.
- Исправление: роль только из сессии по токену.
- Код: `/admin/export` (113–117).
- Доказательство: `evidence/after/T5_block_xrole_header_only.json` (403 без токена/роли), `OK_admin_export.json` (staff может).

5) T6 IDOR файлов
- Проблема: чтение чужих чеков и попытки к private/.
- Исправление: разрешён только собственный чек `files/<me>/receipt.txt`.
- Код: `/files` (118–129).
- Доказательство: `evidence/after/T6_block_files_idor_bob.json` (403 для чужого).

6) T7 Утечка логов
- Проблема: открытый доступ к /debug/logs и утечка токенов/паролей.
- Исправление: доступ только staff; маскирование токенов/паролей в логах.
- Код: `sanitize_log` (51–61), `/debug/logs` (130–134).
- Доказательство: `evidence/after/T7_protect_debug_logs.json` (403).

7) T8 Stored XSS
- Проблема: отзывы вставлялись без экранирования.
- Исправление: `html.escape` при рендере.
- Код: `/reviews/view` (138–140).
- Доказательство: `evidence/after/T8_escape_reviews_html.json` (спецсимволы экранированы).

8) T9 Инструменты ассистента (server‑side enforcement)
- Проблема: отсутствие проверок прав/аргументов; допустимо удаление дерева.
- Исправление: проверка сессии; `read_file` — только свой чек; `export_profiles` — только staff; `delete_tree` — запрещён через API.
- Код: `/assistant/execute` (163–185).
- Доказательства: `evidence/after/T9a_forbid_read_bob_receipt.json`, `T9b_require_staff_export_profiles.json`, `T9c_forbid_delete_tree.json`.

9) T10 Раскрытие деталей ошибок
- Проблема: возврат типа исключения/текста.
- Исправление: 400 для невалидного JSON; общий 500 без внутренних деталей.
- Код: обработчик `make_handler` (ф-я `handle_request`) строки 205–217.
- Доказательство: `evidence/after/T10_safe_error_invalid_json.json` (400 invalid json без stack/типов).

Дополнительно:
- Привязка профиля/чека/контекста ассистента к сессии владельца; корректная валидация `order_id`.

## Остаточные ограничения и риски
- Маршрут `/search` теперь только для staff; это осознанное ограничение для исключения утечек. При необходимости можно реализовать безопасный клиентский поиск.
- Журналирование минимально и маскировано; при расширении логов учитывать PII/секреты.
- Ассистент не выполняет `delete_tree` через API; удаление по‑прежнему возможно только внутри тестовой песочницы и не должно экспонироваться наружу.
