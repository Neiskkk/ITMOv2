# Отчёт 1. Атаки на исходный сервис (фактические проверки до исправлений)

Проведены статический аудит и воспроизведение атак на реальном HTTP‑процессе. Сервис запускался на 127.0.0.1:8066 (см. evidence/before/host.json). Фактические логи исходных `make install` и `make test` сохранены в `practices/practice_06/evidence/before/`.

Подтверждение: встроенные тесты из `lab/` проходят на исходном уязвимом сервисе (см. логи). Ниже — фактические доказательства уязвимостей (файлы с запросом/ответом) и способы повторения. Скрипт проверок: `practices/practice_06/lab/run_checks_before.py`.

## Критичные проблемы (по коду, до проверок)

Обозначения T1…T10 совпадают с THREAT_MODEL.md.

— T1. SQL Injection в профиле по id — ПОДТВЕРЖДЕНО
- Путь: GET /profile?id=...
- Код: `service.py:57` — f-string `SELECT * FROM profiles WHERE id = {query.get('id', '1')}`
- Предпосылки: параметр id не параметризуется и не валидируется.
- Последствия: возможность получения всех профилей, модификации запросов, чтение произвольных данных из таблиц.
- Доказательство: evidence/before/T1_profile_sqli.json (status 200, возвращены оба профиля на `id=1 OR 1=1`).
- Повторение: GET /profile?id=1%20OR%201=1.

— T2. SQL Injection в поиске — ПОДТВЕРЖДЕНО

— T2. SQL Injection в поиске
- Путь: GET /search?q=...
- Код: `service.py:59` — f-string `LIKE '%{query.get('q', '')}%'`.
- Предпосылки: параметр q не параметризуется.
- Последствия: раскрытие/манипуляция данными, обход фильтров.
- Доказательство: evidence/before/T2_search_sqli.json (status 200, оба профиля).
- Повторение: GET /search?q=%25'%20OR%201=1%20--.

— T3. Просмотр всех заказов без аутентификации — ПОДТВЕРЖДЕНО

— T3. Нарушение контроля доступа: просмотр всех заказов
- Путь: GET /orders
- Код: `service.py:61` — `SELECT * FROM orders` без проверки сессии/владельца.
- Предпосылки: маршрут доступен всем, в т.ч. анонимам.
- Последствия: утечка истории заказов и пользовательских ID.
- Доказательство: evidence/before/T3_orders_no_auth.json (status 200, видны все заказы).
- Повторение: GET /orders.

— T4. Клиент может назначить цену — ПОДТВЕРЖДЕНО

— T4. Произвольная цена заказа от клиента
- Путь: POST /orders
- Код: `service.py:69` — `price = body.get('price', self.products[product])`
- Предпосылки: сервер принимает клиентскую цену, игнорируя каталог.
- Последствия: финансовые потери, обход правил ценообразования.
- Доказательство: evidence/before/T4_custom_price.json (status 201, price=1).
- Повторение: POST /orders с {product:"chair", price:1} под токеном alice.

— T5. Эскалация привилегий заголовком X‑Role — ПОДТВЕРЖДЕНО

— T5. Эскалация привилегий заголовком X-Role
- Путь: GET /admin/export
- Код: `service.py:75-77` — проверяется только `headers.get('X-Role') == 'staff'`.
- Предпосылки: роль не извлекается из сессии по токену, а целиком доверяется заголовку клиента.
- Последствия: любой клиент может стать «staff» и получить экспорт профилей.
- Доказательство: evidence/before/T5_admin_export_header_only.json (status 200 на GET /admin/export только с X-Role: staff, без staff‑сессии).
- Повторение: GET /admin/export с заголовком X-Role: staff.

— T6. IDOR файлов — ЧАСТИЧНО ПОДТВЕРЖДЕНО

— T6. IDOR: произвольное чтение файлов внутри песочницы
- Путь: GET /files?user=...&path=...
- Код: `service.py:79-80` — путь конструируется из query; авторизации на владельца нет.
- Предпосылки: `Sandbox` контролирует только границу каталога, но не права доступа.
- Последствия: чтение чеков других пользователей и служебной записки `private/operator-note.txt`.
- Доказательства: 
  - evidence/before/T6_files_idor_bob_receipt.json (status 200, Alice читает чек Bob).
  - evidence/before/T6_files_idor_private_note.json (status 500 с ValueError: sandbox блокирует выход за корень по `..`).
- Вывод: чтение чужих пользовательских файлов возможно; чтение private/ напрямую через `..` отклонено `Sandbox` (граница стенда).
- Повторение: GET /files?user=bob&path=receipt.txt; попытка traversal показывает защиту песочницы.

— T7. Утечка журналов — ПОДТВЕРЖДЕНО

— T7. Утечка журналов запросов
- Путь: GET /debug/logs
- Код: `service.py:81-82` — возвращает логи без аутентификации.
- Предпосылки: маршрут доступен любому клиенту.
- Последствия: утечка токенов, тел запросов, внутренних путей, облегчающая дальнейшие атаки.
- Доказательство: evidence/before/T7_debug_logs_exposed.json (status 200, логи содержат тела запросов и заголовки; токены могут встречаться).
- Повторение: GET /debug/logs.

— T8. Stored XSS в отзывах — ПОДТВЕРЖДЕНО (неэкранированный HTML)

— T8. Хранимая XSS в отзывах
- Путь: POST /reviews, GET /reviews/view
- Код: `service.py:84,87` — текст вставляется в HTML без экранирования, `Content-Type: text/html`.
- Предпосылки: любые данные пользователя будут интерпретированы как HTML/JS.
- Последствия: выполнение JS в браузере оператора/клиента, кража данных.
- Доказательство: evidence/before/T8_reviews_stored_xss.json (status 200, Content-Type: text/html, HTML возвращён как есть). Выполнение JS в браузере не проверялось на этом этапе.
- Повторение: POST /reviews с payload, затем GET /reviews/view.

— T9. Доступ к инструментам ассистента (не prompt injection) — ПОДТВЕРЖДЕНО

— T9. Prompt Injection / злоупотребление инструментами ассистента
- Путь: GET /assistant/context, POST /assistant/execute
- Код: `service.py:88-109` — сервер исполняет инструменты строго по переданному `decision`, без серверной политики и проверки прав относительно сессии.
- Предпосылки: отсутствует серверная авторизация на `read_file`, `export_profiles`, `delete_tree`.
- Последствия: чтение чужих файлов, экспорт профилей, удаление файлов в песочнице.
- Доказательства:
  - evidence/before/T9a_tool_read_bob_receipt.json (status 200, чтение чека Bob).
  - evidence/before/T9b_tool_export_profiles.json (status 200, экспорт профилей).
  - evidence/before/T9c_tool_delete_tree.json и T9c_tool_delete_tree_followup.json (на отдельном экземпляре: удаление корня песочницы подтверждено FileNotFoundError при чтении чека).
- Повторение: POST /assistant/execute с соответствующим decision. Это проверка доступа к инструментам, а не доказательство prompt injection.

— T10. Раскрытие деталей ошибок — ПОДТВЕРЖДЕНО (для некорректного JSON)

— T10. Раскрытие деталей ошибок
- Путь: общий обработчик
- Код: `service.py:128-135` — отвечает `{"error": str(exc), "type": ...}` всем клиентам.
- Предпосылки: текст исключений может содержать внутренние детали.
- Последствия: утечка технической информации, облегчающей атаки.
- Доказательство: evidence/before/T10_error_invalid_json.json (status 500, type: JSONDecodeError, текст ошибки возвращается клиенту). Превышение Content-Length может дать 413 — это отдельный кейс.
- Повторение: POST /login с телом `{not: json}` и заголовком application/json.

## Дополнительные проверки

- Доступ к чужому заказу через /assistant/context — ПОДТВЕРЖДЕНО: evidence/before/A2_assistant_context_foreign_order.json (возвращает заказ Bob).
- SQL-инъекция в order_id контекста — ПОДТВЕРЖДЕНО: evidence/before/A3_assistant_context_order_sqli.json (в prompt попали все заказы).
- Отсутствие аутентификации на чувствительных маршрутах — ПОДТВЕРЖДЕНО: evidence/before/T3_orders_no_auth.json, T7_debug_logs_exposed.json; для /admin/export без заголовка — 403 (evidence/before/A5_admin_export_no_header.json), но заголовок X-Role даёт доступ (T5).
- Некорректный JSON и неверные типы — ПОДТВЕРЖДЕНО: evidence/before/T10_error_invalid_json.json (500 на невалидный JSON), evidence/before/A4_orders_wrong_types.json (400 unknown product).

## Скрипт и воспроизводимость
- Скрипт HTTP-проверок: `practices/practice_06/lab/run_checks_before.py`. Он поднимает сервер при необходимости, выполняет T1–T10 и доп. проверки, сохраняет артефакты и отдельно запускает экземпляр для delete_tree.
- Хост и каталог песочницы зафиксированы в `evidence/before/host*.json`.


## Замечания по границам стенда
- `sandbox.py` эффективно удерживает операции внутри временного каталога (проверки путей, запрет symlink-escape). Это сохраняет внешнюю систему в безопасности, но не решает авторизацию внутри песочницы — это обязанность сервиса.
- HTTP-сервер слушает только 127.0.0.1; в лаборатории нет удалённых вызовов и выполнения кода/шелла — это границы, которые необходимо сохранить и после исправлений.
