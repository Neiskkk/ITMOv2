# Анализ процесса: AS IS и TO BE

## AS IS

По TRAINING_PR.diff добавлены:
- метод `ReviewService.review(diff)` — формирует простой prompt: "Review this pull request and find problems:\n{diff}", отправляет сырой diff во внешний `LLM.generate`, возвращает `{"comment": answer}`;
- endpoint `POST /api/reviews` — принимает `payload: { diff }`, вызывает `review_service.review` и отдаёт результат как есть.

Фактический процесс: Клиент → API → ReviewService → LLM (без ограничений) → ответ `comment`.

Пробелы относительно правил из CASE.md:
- SEC-1: нет редактирования секретов в diff;
- API-1: нет проверки/отклонения диффов > 20 000 символов;
- REL-1: нет таймаута 10 с и контролируемой ошибки;
- OUT-1: схема ответа не соблюдена (нет `summary/risks/checks`, только `comment`);
- QA-1: риски не привязываются к файлу/строке и не подтверждаются строкой diff;
- OBS-1: нет описанного минимального логирования.


## TO BE

Небольшое целевое изменение процесса: перед вызовом LLM сервис фильтрует вход (SEC-1, API-1), формирует master prompt с Context Pack, вызывает LLM с таймаутом (REL-1), нормализует ответ к OUT-1 и ограничивает `risks ≤ 3`; при ошибке возвращает контролируемый ответ. API отдаёт `summary/risks/checks`.

```mermaid
flowchart LR
    A[POST /api/reviews (diff)] --> B[Фильтр входа\nSEC-1: редактирование секретов\nAPI-1: длина ≤ 20k]
    B --> C[Сбор master prompt\n+ Context Pack]
    C --> D[LLM.generate\nтаймаут 10с]
    D --> E[Парсинг к OUT-1\nrisks ≤ 3, QA-1 подтверждение]
    E --> F[Ответ API: summary/risks/checks]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Вход в LLM | В сыром виде весь diff | Секреты редактируются (SEC-1) | Отправить diff с тестовым token; в prompt должен быть [REDACTED] |
| Формат ответа | `{"comment": ...}` | `summary`, `risks[≤3]{file,line,evidence,risk}`, `checks` (OUT-1) | Сравнить JSON с схемой; убедиться, что `risks` ≤ 3 и есть `file/line/evidence` |
| Ограничение размера | Нет | HTTP 413 при diff > 20 000 символов (API-1) | Отправить 21 000+ символов; получить 413 |
| Таймаут/ошибка | Нет обработки | Таймаут 10с и контролируемый ответ (REL-1) | Замокать LLM на 11с; получить предсказуемый error-пэйлоад |
| Подтверждение рисков | Не требуется | Риск включается только с доказательством из diff (QA-1) | Риск без `evidence` не попадает в ответ |

## Как использовали AI

- Для чего: сравнить два запуска по одному diff и зафиксировать разницу качества (структура, подтверждённость, границы).
- Тип промпта: Запуск 1 — короткий свободный; Запуск 2 — Master Prompt v1 с Context Pack.
- Строка в [`prompts.md`](prompts.md): «Ниже diff учебного PR. Посмотри PR и найди проблемы.»; «Master Prompt v1».
- Что проверили и исправили сами: валидацию формата OUT-1 и QA-1, ограничение `risks ≤ 3`, наличие ссылок на файл/строку и воспроизводимых проверок.
