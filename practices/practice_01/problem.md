# Проблема и метрики

## Проблема

- Пользователь:
  - Разработчик/ревьюер, использующий сервис для автоматической проверки PR по diff.
- Ситуация:
  - В учебном PR добавлены сервисный метод `review` и HTTP-эндпоинт `POST /api/reviews`, которые принимают diff и отправляют его во внешний LLM. См. TRAINING_PR.diff.
- Что происходит сейчас:
  - Diff отправляется в LLM без маскирования секретов (нарушение SEC-1);
  - Нет явного ограничения на длину входного diff и возврата 413 (нарушение API-1);
  - Формат ответа возвращается как `{\"comment\": answer}`, что не соответствует требуемой структуре OUT-1 (`summary`, `risks`, `checks`).
- Почему это мешает пользователю или бизнесу:
  - Риск утечки секретов при передаче diff во внешний LLM;
  - Клиентские компоненты не могут надёжно парсить результат, так как контракт ответа нарушен;
  - Отсутствие защиты по размеру входа может приводить к отказам сервиса по таймаутам/413 на границе, но не на уровне нашего API.
- Что не входит в задачу:
  - Approve/merge PR и изменение исходного кода вне учебного diff;
  - Реализация логирования, таймаутов и ретраев — не наблюдаются в текущем diff и могут быть реализованы вне показанного участка.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля ответов, соответствующих OUT-1 | Проверка JSON-схемой: наличие `summary`, `risks` (<=3, поля `file`,`line`,`evidence`,`risk`), `checks` | 100% соответствие | На каждом ответе сервиса | Автотесты API, контрактные тесты |
| Эффективность маскирования секретов (SEC-1) | Тестовый diff с фейковым token; проверка, что в prompt подставлено [REDACTED] | 100% кейсов проходят | При релизе и регрессе | Интеграционный тест с трассировкой prompt |
| Соблюдение лимита API-1 | Отправка diff > 20 000 символов — ожидание HTTP 413 | 100% кейсов возвращают 413 | На запросах с превышением | Функциональные тесты API |

## Почему изменение метрики подтвердит решение проблемы

Если ответы соответствуют OUT-1, клиентские компоненты могут стабильно обрабатывать результат. Исправная маскировка исключает утечку секретов при передаче diff во внешний LLM. Возврат 413 на слишком больших diff предотвращает деградацию и соответствует контракту API.
