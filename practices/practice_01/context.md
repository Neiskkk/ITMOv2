## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. (CASE.md)
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413. (CASE.md)
- OUT-1: ответ должен содержать summary, массив risks (макс. 3) и массив checks; в risks элементы с полями file, line, evidence, risk. (CASE.md)
- SCOPE-1: сервис только советует; не пишет код и не выполняет действия в GitHub. (CASE.md)
- QA-1: риск включается в ответ, только если подтверждён строкой diff или правилом репозитория. (CASE.md)

### Формат входа и результата

- Вход: строка diff PR, передаваемая в POST /api/reviews. (TRAINING_PR.diff)
- Ожидаемый результат: структура по OUT-1 — summary, risks[<=3 {file,line,evidence,risk}], checks[]. (CASE.md)

### Ограничения и запрещённые действия

- Не изменять исходный код и не выполнять approve/merge (SCOPE-1). (CASE.md)
- Не отправлять секреты во внешний LLM — требуется редактирование/маскирование входа (SEC-1). (CASE.md)

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED]. (CASE.md, пример)

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок. (CASE.md, пример)

### Что пока неизвестно

- Где именно реализована маскировка секретов (если есть) — на уровне LLM клиента, middleware или сервиса. (неизвестно)
- Кто потребляет API и накладывает ли контракт на схему ответа на уровне gateway. (неизвестно)
- Реализованы ли таймауты и ретраи для внешнего LLM вне показанного diff. (неизвестно)

## Как использовали AI

- Для чего:
  - Сбор контекста и правил (Context Pack), формирование Master Prompt v1 и ревью TRAINING_PR.diff.
- Тип промпта:
  - Структурированный (master prompt) для второго запуска.
- Строка в [`prompts.md`](prompts.md):
  - Раздел «Master Prompt v1» и запись P1-02 (когда будет выполнен запуск).
- Что проверили и исправили сами:
  - Отобрали только релевантные правила (SEC-1, API-1, OUT-1, SCOPE-1, QA-1), обозначили неизвестные, подготовили проверяемые выводы с evidence.
