# AGENTS.md — технические инструкции

## 1. Область действия

Инструкции распространяются на весь каталог `practices/practice_04`.

Источник функциональных требований — `requirements.md`. При противоречии между реализацией и требованиями сначала остановись и запроси уточнение. Не расширяй scope без согласования.

## 2. Назначение проекта

Одностраничный русскоязычный лендинг приюта для животных. Целевое действие — выбор питомца в каталоге и отправка заявки на знакомство.

## 3. Технологический стек

- HTML5.
- CSS3 без препроцессоров.
- JavaScript ES2022+, только браузерный DOM API.
- Без React, Vue, Angular и других JS-фреймворков.
- Без runtime-зависимостей и CDN-библиотек.
- Без backend, базы данных и внешних API.
- Локальный запуск через статический HTTP-сервер.
- Кодировка всех текстовых файлов: UTF-8.

## 4. Структура проекта

Поддерживай следующую структуру:

```text
practice_04/
├── AGENTS.md
├── requirements.md
├── README.md
├── index.html
├── styles.css
├── script.js
└── assets/
    └── images/
```

Не создавай дополнительные уровни каталогов и сборочную систему без необходимости.

## 5. Команды

Локальный запуск из `practices/practice_04`:

```bash
python3 -m http.server 8000
```

Страница должна открываться по адресу `http://localhost:8000`.

Минимальная статическая проверка JavaScript:

```bash
node --check script.js
```

Если Node.js отсутствует, зафиксируй это как ограничение и выполни ручную проверку в браузере.

## 6. Архитектура HTML

Используй один файл `index.html` и семантическую структуру:

- `header` — логотип, навигация, CTA;
- `main`;
- `section#hero`;
- `section#about`;
- `section#pets`;
- `section#help`;
- `section#application`;
- `section#contacts`;
- `footer`.

Навигационные ссылки должны вести к существующим идентификаторам секций. На странице допускается только один `h1`; заголовки остальных разделов — `h2`.

## 7. Архитектура CSS

- Подключай один файл `styles.css`.
- Используй CSS custom properties в `:root` для цветов, отступов, радиусов и теней.
- Применяй mobile-first подход.
- Базовая поддерживаемая ширина: от 320 px.
- Контрольные диапазоны: мобильный до 767 px, планшет 768–1023 px, desktop от 1024 px.
- Используй Flexbox и Grid; абсолютное позиционирование не должно быть основой макета.
- Не допускай горизонтальную прокрутку.
- Для интерактивных элементов обязательны `:hover`, `:focus-visible`, `:active` и `:disabled`, если применимо.
- Уважай `prefers-reduced-motion`; не добавляй обязательные сложные анимации.

## 8. Архитектура JavaScript

Подключай один файл `script.js` с атрибутом `defer`.

Данные животных храни в массиве объектов:

```js
{
  id: "string",
  name: "string",
  species: "cat" | "dog",
  age: "string",
  sex: "string",
  image: "string",
  alt: "string",
  description: "string"
}
```

Минимальные функции:

- `renderAnimals(filter)` — вывод карточек по выбранному фильтру;
- `setActiveFilter(filter)` — обновление состояния фильтров;
- `openApplication(animalId)` — переход к форме и выбор питомца;
- `validateApplication(formData)` — возврат ошибок по полям;
- `handleApplicationSubmit(event)` — предотвращение перезагрузки и обработка формы.

Не записывай персональные данные в `localStorage`, `sessionStorage`, cookie или URL. Не выполняй сетевые запросы.

## 9. Соглашения реализации

- Используй `const` по умолчанию и `let` только при переназначении.
- Не используй `var`, inline-обработчики событий и `innerHTML` для пользовательских данных.
- DOM-элементы связывай через устойчивые `id` и `data-*` атрибуты.
- Имена переменных и функций — английские, видимый текст интерфейса — русский.
- Функции должны решать одну задачу.
- Не дублируй данные карточек одновременно в HTML и JavaScript.
- Ошибки формы выводи рядом с полем и связывай через `aria-describedby`.
- Состояние ошибки отмечай `aria-invalid="true"`.

## 10. Доступность

- Все изображения имеют содержательный `alt`.
- Каждое поле формы связано с `label`.
- Все функции доступны с клавиатуры.
- Фокус визуально заметен.
- После невалидной отправки фокус переходит на первое ошибочное поле.
- Сообщение об успехе использует `role="status"` или `aria-live="polite"`.
- Контраст текста и элементов управления должен соответствовать WCAG AA.
- Нельзя передавать смысл только цветом.

## 11. Контент и данные

- Используй только демонстрационные данные животных.
- Не выдумывай реальные адреса, телефоны, отзывы, награды и реквизиты.
- Изображения должны быть локальными либо иметь согласованную лицензию и источник.
- При отсутствии изображений используй локальные заглушки с корректным `alt`.

## 12. Ограничения изменений

- Не меняй файлы вне `practices/practice_04`.
- Не добавляй зависимости и package manager без согласования.
- Не выполняй commit, push и публикацию без прямой команды пользователя.
- Перед изменением перечисли планируемые файлы.
- После изменения покажи `git diff` и результаты проверок.

## 13. Definition of Done

Работа готова, когда:

- реализованы обе фичи из `requirements.md`;
- все критерии приёмки пройдены;
- `node --check script.js` не сообщает ошибок;
- страница работает через локальный HTTP-сервер;
- нет ошибок в консоли браузера;
- проверены ширины 320, 768 и 1440 px;
- проверена клавиатурная навигация;
- README содержит команды запуска и ручной чек-лист;
- изменены только файлы `practices/practice_04`.
