# Чек-лист: Логика «Избранные питомцы» (001-favorites-пets)

Статус: Draft (для согласования)

Этот чек-лист покрывает пункты 1–11 задания для логической части. Используется для ручной валидации перед реализацией.

## 1. Хранение множества стабильных id (персистенция)
- [ ] Используется множество стабильных id питомцев (Set в памяти, массив строк в хранилище).
- [ ] Персистенция между перезагрузками через localStorage под ключом shelter.catalog.favorites.
- [ ] Нет ограничений на количество избранных.
- [ ] При изменении избранного оперативное состояние обновляется всегда; попытка записи в localStorage выполняется синхронно.

## 2. Формат данных и ключ
- [ ] Ключ localStorage: shelter.catalog.favorites.
- [ ] Значение — JSON-массив строковых id без метаданных (например, ["cat-1","dog-2"]).
- [ ] Не хранить персональные данные.

## 3. Чтение и валидация при запуске
- [ ] При отсутствии ключа используется пустой массив [].
- [ ] Парсинг JSON защищён try/catch; SyntaxError не ломает приложение.
- [ ] Допустим только массив; элементы НЕ конвертируются в строки.
- [ ] Принимаются только элементы типа string, не пустые, соответствующие существующим id каталога.
- [ ] Дубликаты удаляются (Set); порядок не важен.
- [ ] Неизвестные id (нет в каталоге) игнорируются.
- [ ] При отличиях от исходного значения хранилище перезаписывается приведённой версией при первой возможности.
- [ ] При повреждённом JSON выполняется исправляющая запись [] в localStorage: при успехе persisted=true и code=CORRUPTED_DATA_RECOVERED; при неудаче persisted=false с тем же кодом.

## 4. Недоступность localStorage
- [ ] При ошибках доступа (SecurityError / QuotaExceeded / приватный режим) логика продолжает работу в памяти.
- [ ] UI получает понятное ненавязчивое сообщение об ошибке персистенции (однократно на сессию).
- [ ] persisted=false возвращается ТОЛЬКО для операций чтения/записи, которые действительно завершились ошибкой; иначе persisted=true.
- [ ] Состояние теряется после перезагрузки, если persisted=false.
- [ ] При восстановлении доступности выполняется отложенная синхронизация текущего состояния.

## 5. Операции
- [ ] getFavoritesState возвращает { favoritesIds[], favoritesCount, persisted } (без утечки внутреннего Set).
- [ ] isFavorite(id) корректно отражает членство.
- [ ] addFavorite(id) идемпотентна; UNKNOWN_ID при несуществующем id.
- [ ] removeFavorite(id) идемпотентна.
- [ ] toggleFavorite(id) возвращает новое isFavorite, count и persisted.
- [ ] Результаты содержат поля ok, changed, persisted, code/message при ошибках; persisted присутствует во всех Result, включая UNKNOWN_ID.

## 6. Совместимость с поиском и фильтрами
- [ ] При favoritesOnly=false поиск/фильтры применяются ко всем животным.
- [ ] При favoritesOnly=true базовый набор — только избранные; затем поиск по имени (case-insensitive) и фильтр вида.
- [ ] Снятие избранного в режиме favoritesOnly немедленно исключает карточку из списка; пустое состояние без мерцаний.

## 7. Сценарии (прогон)
- [ ] Основной: добавить избранное → включить «Только избранные» → перезагрузка → состояние восстановлено (persisted=true при доступном localStorage).
- [ ] Ошибочный: повреждённый JSON → выполняется исправляющая запись []; при успехе persisted=true и code=CORRUPTED_DATA_RECOVERED; при неуспехе persisted=false и тот же код.
- [ ] Ошибочный: недоступный localStorage → persisted=false только для неудавшихся чтений/записей; операции работают в памяти; UI уведомлён.
- [ ] Ошибочный: UNKNOWN_ID при toggle неизвестного id.
- [ ] Граничный: дубликаты в хранилище → удалены; перезапись произведена.
- [ ] Граничный: пустое множество при включённом favoritesOnly → пустое состояние.
- [ ] Регрессионный: поиск и фильтры без favoritesOnly работают как раньше; форма заявки не затронута.

## 8. Контракт UI ↔ Логика
- [ ] Начальное состояние: favoritesIds[], favoritesOnlyDefault=false, persisted флаг предоставлен UI.
- [ ] Событие onFavoritesChanged содержит changedIds?, favoritesIds, count, persisted, message?.
- [ ] Сигналы: toggleFavorite(id), setFavoritesOnly(bool), requestFavoritesState().
- [ ] Успех/ошибка операций: ok/false, code/message согласно спецификации.

## 9. Ответы на вопросы UI
- [ ] Избранное сохраняется между сессиями (при доступном localStorage).
- [ ] Нет лимита количества избранных.
- [ ] При ошибке хранения — состояние в памяти, persisted=false, ненавязчивое сообщение для UI.

## 10. Диаграмма взаимодействий
- [ ] Mermaid sequenceDiagram добавлена в logic-spec.md; отражает кейсы: валидные данные, повреждённый JSON, недоступное хранилище, toggle, favoritesOnly.

## 11. Измеримые критерии (Acceptance)
- [ ] AC-LOGIC-001: 100% восстановление валидных id при запуске.
- [ ] AC-LOGIC-002: Повреждённый JSON не ломает; выполняется исправляющая запись []. При успехе persisted=true и code=CORRUPTED_DATA_RECOVERED; при неуспехе persisted=false и тот же код.
- [ ] AC-LOGIC-003: Недоступный localStorage → persisted=false возвращается только для реально неудачных операций чтения/записи; сообщение показано один раз.
- [ ] AC-LOGIC-004: Дубликаты устраняются и не возвращаются при последующих чтениях.
- [ ] AC-LOGIC-005: Комбинации favoritesOnly + поиск + вид дают ожидаемые результаты во всех проверках.
- [ ] AC-LOGIC-006: Идемпотентность add/remove соблюдена.
- [ ] AC-LOGIC-007: Время ответа toggle→render ≤ 50 мс при N≤100 карточек (ручная метрика/профилирование).

### Ручные шаги проверки (пример)
1) Очистить localStorage; перезагрузить страницу; убедиться, что начальное favorites пусто и persisted=true (если доступно).
2) Добавить 3 карточки в избранное; перезагрузить; убедиться, что восстановились 3 id.
3) Включить «Только избранные», применить поиск по имени и фильтр вида; сверить набор.
4) Вручную повредить значение в localStorage (некорректный JSON); перезагрузить; убедиться в безопасном восстановлении.
5) Эмулировать недоступность localStorage (приватный режим/эмуляция ошибок); проверить persisted=false и сообщения.
6) Проверить идемпотентность add/remove и корректность toggle на уже избранных/неизбранных.
