# Requirements — лендинг приюта для животных

## 1. Product

Одностраничный русскоязычный лендинг вымышленного приюта для животных.

Цель продукта: помочь посетителю выбрать питомца и отправить заявку на знакомство.

Основная метрика учебной версии: пользователь может пройти сценарий «открыть каталог → выбрать животное → валидно отправить форму» без перезагрузки страницы и ошибок JavaScript.

## 2. Технические ограничения

- Стек: HTML5, CSS3, vanilla JavaScript ES2022+.
- Один HTML-файл: `index.html`.
- Один файл стилей: `styles.css`.
- Один файл логики: `script.js`.
- Без JS-фреймворков, CDN-библиотек и runtime npm-зависимостей.
- Без backend и внешних API.
- Интерфейс и сообщения: русский язык.
- Данные животных: локальный массив объектов в `script.js`.
- Отправка формы: клиентская имитация без сетевого запроса.
- Поддерживаемые браузеры: актуальные Chrome, Firefox, Edge и Safari.
- Поддерживаемая ширина viewport: от 320 px.

## 3. Структура страницы

Обязательные секции:

1. Header с логотипом, якорной навигацией и CTA «Выбрать питомца».
2. Hero с `h1`, кратким описанием и ссылкой на каталог.
3. «О приюте».
4. «Наши питомцы» с фильтрами и карточками.
5. «Как помочь».
6. «Заявка на знакомство».
7. «Контакты».
8. Footer.

## 4. Feature 1 — каталог и фильтрация животных

### 4.1. Назначение

Feature 1 представляет собой интерактивный каталог животных приюта. Она помогает посетителю быстро увидеть доступных питомцев, сузить список по виду и перейти от просмотра конкретной карточки к началу знакомства.

**Пользовательская история:** как потенциальный хозяин, я хочу посмотреть кошек и собак, отфильтровать их и выбрать понравившегося питомца, чтобы перейти к заявке именно на него.

**Основной сценарий:**

1. Пользователь открывает страницу и сразу видит полный каталог.
2. Пользователь переключает фильтр «Все», «Кошки» или «Собаки».
3. Каталог без перезагрузки показывает только подходящие карточки.
4. Пользователь изучает имя, фотографию и краткую информацию о животном.
5. Пользователь нажимает «Познакомиться» на выбранной карточке.
6. Страница переходит к блоку заявки, а выбранный питомец автоматически подставляется в форму.

**Результат фичи:** в интерфейсе однозначно зафиксирован ID выбранного животного, и пользователь готов перейти к заполнению заявки.

**Граница фичи:** Feature 1 отвечает только за данные каталога, отображение карточек, фильтрацию и передачу выбранного ID животного в форму. Проверка контактных данных и отправка формы относятся к Feature 2.

### 4.2. Входные данные

В `script.js` должен находиться массив минимум из шести объектов:

- минимум три объекта с `species: "cat"`;
- минимум три объекта с `species: "dog"`;
- уникальный строковый `id` у каждого объекта;
- обязательные поля: `id`, `name`, `species`, `age`, `sex`, `image`, `alt`, `description`.

### 4.3. UI

В секции `#pets` должны присутствовать:

- группа фильтров «Все», «Кошки», «Собаки»;
- контейнер карточек;
- сообщение пустого состояния, скрытое при наличии результатов.

Карточка содержит:

- изображение;
- имя;
- вид, возраст и пол;
- краткое описание;
- кнопку «Познакомиться».

### 4.4. Поведение

- Начальное состояние фильтра — `all`.
- Нажатие фильтра обновляет карточки без перезагрузки.
- Активный фильтр получает визуальное состояние и `aria-pressed="true"`.
- Фильтрация не изменяет исходный массив данных.
- Для неизвестного или пустого результата показывается текст «По выбранному фильтру питомцев пока нет».
- Кнопка карточки вызывает `openApplication(animalId)`.
- После вызова выбранное животное устанавливается в форме, секция `#application` прокручивается в область видимости, фокус переводится на первое поле для ввода данных пользователя.

### 4.5. Критерии приёмки

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| F1-01 | Первое открытие страницы | Отображаются все карточки; активен фильтр «Все» |
| F1-02 | Нажатие «Кошки» | Отображаются только объекты `species: "cat"` |
| F1-03 | Нажатие «Собаки» | Отображаются только объекты `species: "dog"` |
| F1-04 | Возврат к «Все» | Отображается полный набор без дубликатов |
| F1-05 | Активация фильтра клавишей Enter/Space | Результат совпадает с кликом |
| F1-06 | Нажатие «Познакомиться» у карточки | В форме выбрано животное с соответствующим `id` |
| F1-07 | Пустой результат | Карточки скрыты, показано сообщение пустого состояния |

## 5. Feature 2 — форма заявки на знакомство

### 5.1. Назначение

Feature 2 представляет собой клиентскую форму заявки на знакомство с питомцем. Она принимает выбранное в каталоге животное и контактные данные посетителя, проверяет введённые значения и имитирует успешную отправку без backend и сетевого запроса.

**Пользовательская история:** как потенциальный хозяин, я хочу оставить корректные контактные данные и комментарий по выбранному питомцу, чтобы приют мог связаться со мной для знакомства.

**Основной сценарий:**

1. Пользователь переходит к форме из карточки питомца или самостоятельно.
2. В форме отображается ранее выбранное животное; при необходимости его можно выбрать из допустимого списка.
3. Пользователь вводит имя, хотя бы один канал связи, необязательный комментарий и подтверждает согласие.
4. При отправке форма проверяет все поля на стороне браузера.
5. Если есть ошибки, отправка блокируется, рядом с полями появляются понятные сообщения, а фокус переходит к первой ошибке.
6. После исправления ошибок пользователь повторно отправляет форму.
7. При валидных данных показывается подтверждение, персональные поля очищаются, а выбранный питомец остаётся указанным.

**Результат фичи:** пользователь получает доступное сообщение об успешном принятии заявки без перезагрузки страницы, изменения URL или передачи данных по сети.

**Граница фичи:** Feature 2 отвечает за интерфейс формы, клиентскую валидацию, доступные сообщения об ошибках и имитацию успеха. Реальная отправка, хранение данных, CRM и обратная связь сотрудника приюта находятся вне scope.

### 5.2. Поля

| Поле | Тип | Обязательность | Правило |
|---|---|---:|---|
| Питомец | `select` или readonly-поле | да | Значение соответствует существующему `animal.id` |
| Имя | `text` | да | После trim от 2 до 60 символов |
| Телефон | `tel` | условно | Требуется телефон или email; допустимы цифры, пробелы, `+`, `-`, скобки; не менее 10 цифр |
| Email | `email` | условно | Требуется телефон или email; проверка браузером и JavaScript |
| Комментарий | `textarea` | нет | Не более 500 символов |
| Согласие | `checkbox` | да | Должно быть отмечено |

### 5.3. Валидация

- Отправка обрабатывается через событие `submit` с `preventDefault()`.
- Проверяются все правила из таблицы полей.
- Должен быть заполнен минимум один канал связи: телефон или email.
- Пробельные значения считаются пустыми.
- Сообщение об ошибке выводится рядом с полем.
- Невалидное поле получает `aria-invalid="true"`.
- Ошибка связана с полем через `aria-describedby`.
- После проверки фокус переводится на первое невалидное поле.
- При повторной проверке исправленная ошибка удаляется.

### 5.4. Успешная отправка

Если данные валидны:

1. Сетевой запрос не выполняется.
2. Отображается сообщение «Заявка принята. Мы свяжемся с вами».
3. Сообщение доступно через `aria-live="polite"`.
4. Имя, телефон, email, комментарий и согласие очищаются.
5. Выбранный питомец сохраняется в форме до следующего выбора из каталога.
6. Перезагрузка страницы не происходит.
7. Персональные данные не сохраняются в браузерное хранилище или URL.

### 5.5. Критерии приёмки

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| F2-01 | Отправка пустой формы | Отправка заблокирована; показаны ошибки обязательных данных |
| F2-02 | Имя из одного символа | Показана ошибка длины имени |
| F2-03 | Нет телефона и email | Показано требование указать один канал связи |
| F2-04 | Телефон содержит меньше 10 цифр | Показана ошибка телефона |
| F2-05 | Некорректный email | Показана ошибка email |
| F2-06 | Комментарий длиннее 500 символов | Отправка заблокирована |
| F2-07 | Согласие не отмечено | Отправка заблокирована |
| F2-08 | Все данные валидны | Показано подтверждение, сетевой запрос отсутствует |
| F2-09 | Питомец выбран из карточки | Форма содержит правильное животное |
| F2-10 | Исправление поля | Ошибка этого поля удаляется при повторной проверке |

## 6. Нефункциональные требования

### 6.1. Адаптивность

- На 320 px контент не выходит за границы viewport.
- На мобильном карточки располагаются в одну колонку.
- На планшете и desktop количество колонок увеличивается по доступной ширине.
- Размер интерактивной области кнопок и фильтров — не менее 44×44 px.

### 6.2. Доступность

- Семантические `header`, `nav`, `main`, `section`, `footer`.
- Один `h1`; последовательная иерархия заголовков.
- Связанные `label` для всех полей.
- Содержательные `alt` для изображений.
- Полная клавиатурная доступность.
- Видимый `:focus-visible`.
- Контраст не ниже WCAG AA.
- Ошибки и состояния не обозначаются только цветом.

### 6.3. Производительность и безопасность

- Не выполнять сетевые запросы после загрузки локальных ресурсов.
- Не сохранять персональные данные.
- Не использовать `eval` и inline JavaScript.
- Не вставлять пользовательские значения через `innerHTML`.
- Изображения должны иметь заданные размеры и `loading="lazy"`, кроме hero-изображения.
- Ошибки и предупреждения приложения в консоли отсутствуют.

## 7. Вне scope

- Backend и реальная отправка заявок.
- Авторизация и личный кабинет.
- Административная панель.
- Онлайн-оплата.
- Реальные персональные данные, адреса и реквизиты.
- Интеграции с CRM, картами, аналитикой и социальными сетями.
